Kovan technical review

Snapshot: 5910f01 plus uncommitted Task 7 delegation work, 2026-10-25. Verdict: Not ready for deployment

The implemented architecture is directionally consistent with Stellar smart accounts, SAC USDC, and x402 auth-entry settlement. The policy, frozen account, and pool lifecycle compile and have useful negative tests. The remaining gaps affect the core accounting and authorization promises, so passing tests do not yet establish the design invariants.

Findings

SeverityFindingRequired fix
Highclose has no closed-state guard, and amend accepts closed agents. Repeated subtraction or amendment corrupts the pool invariant; with child covenants, repeated child close can inflate the parent limit.Model allowed transitions explicitly. Reject double close and amend-after-close; add regression tests before delegation.
HighThe covenant checks revoked before recognizing pool returns. This blocks agent-authorized return_funds and direct USDC returns after revocation, contrary to the stated invariant.Allow only the validated return-to-pool contexts before the revoke guard; keep draw, spend, calls, settle, dispute, and delegate blocked as designed.
HighSDK 28 is built with Stellar CLI 26.1.0. The live testnet is protocol 29 and the CLI reports incomplete support for its settings.Use CLI 28.1.0+ with SDK 28, pin it in CI/tooling, and rerun build, simulation, and deployment checks.
MediumAll current contract tests pass, but the central external-ed25519 AuthPayload → __check_auth → Policy::enforce flow is not tested without mocks.Finish the planned four signed auth-entry tests and one live x402 C-account settlement.
MediumNo typed contract events exist for material state transitions.Publish and test events for fund, create, draw, return, revoke, amend, settle, close, dispute, resolve, and delegate.
MediumVectors and recursive child traversal are unbounded.Cap allowlists, call rules, child count, and hierarchy depth; test near network resource limits.
LowFormatting and strict Clippy gates fail; the pool fixture uses an unnecessary unsafe lifetime transmute.Run formatter, fix lint, and store Env/Address in the fixture while creating clients on demand.

Skill alignment

Matches: smart-contracts, assets, and agentic-payments describe the correct Stellar primitives. SAC/G-account trustline separation is correct, C-accounts can hold SAC balances without trustlines, and the x402 exact specification supports C-account auth-entry payers.

Needs updating: the local smart-contract skill is written against protocol 27 while this project is on SDK 28/testnet protocol 29. The generic x402 buyer recipe assumes a G-account signer; Kovan's custom C-account payload builder is therefore a project-specific extension and still needs the planned signed and live tests.
